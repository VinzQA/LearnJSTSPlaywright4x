3. In Scope and Out of Scope

3.1 In-Scope Test Items (Phase 1 Playwright TS Automation)

  • Page Load & Metadata (REQ-LOGIN-001): HTTP 200 verification, page title assertion (Baker Trader ERP), favicon, and layout container loading.
  • Valid Authentication (REQ-LOGIN-002): Successful login with valid admin credentials, receipt of JWT bearer token, and deterministic navigation to the staff dashboard (/).
  • Invalid Credentials Handling (REQ-LOGIN-003): Rejection of incorrect email/password combinations with user-friendly alert message (Email or password is incorrect.).
  • Empty Credentials Validation (REQ-LOGIN-004): Client-side form submission prevention when email or password is left blank.
  • Special Characters & Boundary Inputs (REQ-LOGIN-005): Input tolerance for unicode, accents, quotes, and SQL injection syntax fragments.
  • Role-Based Access Control (REQ-LOGIN-006): Verification of privileged access rights for admin role versus standard employee restrictions.
  • Cross-Browser Compatibility (REQ-LOGIN-007): Headless and headed test execution across Chromium, Firefox, and WebKit desktop browser engines.

  • Native Mobile Applications (REQ-LOGIN-008): Dedicated native iOS/Android binary builds (testing restricted to responsive web app).
  • Physical Hardware Lab Matrix (REQ-LOGIN-009): Testing on physical mobile hardware devices.
  • Non-Desktop Screen Resolutions (REQ-LOGIN-010): Viewports below 360px and 4K ultra-wide monitors.
  • Backend Penetration Testing: Volumetric DDoS attacks and direct database stress testing without authorization.

5. Test Approach, Levels, and Types

5.1 Multi-Tier Test Architecture

Testing follows a risk-based pyramid utilizing Playwright with TypeScript to provide deterministic E2E assertions.

  • Component & Contract Level: Validate react-hook-form schema triggers on blur, and verify API responses from /api/auth/login (HTTP 200, 401, 403, 429).
  • End-to-End System Level: Implement Page Object Model (POM) architecture isolating page locators and interaction flows from assertion logic.
  • Regression Level: Maintain a fast, headless test suite executed on pull requests to prevent regressions in core authentication flows.

5.2 Test Types

  • Functional Testing: Form submission, validation messaging, credential verification, and state navigation.
  • Security Testing: Verify password masking, show/hide toggle behavior, and absence of credential logging in browser console/network logs.
  • Two-Factor Authentication (TOTP) Workflow: Handle totp_required response payloads and transition to the 6-digit verification code input.
  • Cross-Browser Compatibility: Parallel execution across Chromium, Firefox, and WebKit desktop browser engines.
